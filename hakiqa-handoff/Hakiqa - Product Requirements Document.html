1. What Hakiqa Is

Hakiqa is a single operating system for a small or growing business owner in Kenya — replacing a stack of notebooks, WhatsApp groups, and disconnected apps with one place to run sales, stock, staff, customers, and money, plus a CEO-level view that explains what the numbers mean, not just what they are.

The product is mode-aware at the data layer: a single business selects one "Business Mode" (or a Mixed mode) in Settings, and every app — Home, POS, Analytics, CRM, Inventory, Reports — reshapes its content, vocabulary, and KPIs to match, without the owner configuring each app individually.

2. Information Architecture

2.1 Navigation model

  • Rail (left, 76px) — global icon nav: Home, core apps for the current mode, Calendar, Settings, avatar. Present on every app page.
  • App-top header — per page: back button + <h1> naming the app group (not the individual page), a centered pill-nav listing that group's own sub-views, and right-aligned actions (search, notifications, avatar).
  • Rule: pill-nav tabs are for an app's own sub-views only (e.g. Analytics: Revenue/Leaderboard/Customers/Inventory/Reports/Exceptions). They never point at another app group. Cross-links to other apps live in-page instead (a menu action, a card link).
  • Orphan rule: every page must have a real entry point from somewhere a user would plausibly already be — a rail icon, a pill-nav tab, or a card/link inside an existing page. No standalone page is reachable only by typing a URL.

3. Design System

3.1 Visual language

  • Typography: Urbanist, single family throughout.
  • Color: navy, olive, burgundy, deep-rust orange as the four brand hues; no bright yellow/lilac; numbers comma-formatted (K/M-abbreviated only on KPI hero tiles).
  • No emoji anywhere — every icon is an inline stroke SVG matching the rail/pill-nav/icon-button style. Emoji only appear when quoting real chat content (WhatsApp mockups).
  • Hero card — a deep solid-color card (radial corner glow + faint diagonal sheen + white text) for the single most important number in a row. Exactly one hero card per row/group; everything else stays plain white.
  • Haki Tip — the mascot-guided callout component, five emotional variants (tip / advice / warning / announce / alert), used for contextual guidance, warnings, and mismatched-input coaching. User-dismissible via an ×.
  • Shared card primitive (.mp-card) and a shared multi-stat hero band (.hero-stats) now live once in assets/app-shell.css; new pages should consume these rather than redefining card CSS locally.

3.2 Shared source of truth

All shell chrome (rail, app-top, pill-nav, search box, hero-card system, Haki Tip, shared card styles) lives in assets/app-shell.css and is loaded by every page. assets/business-mode.js holds the Business Mode registry, per-mode Home dashboard data (stats + advice, each with a destination link), and a bmModeCheck() helper that shows a non-blocking mismatch banner on vertical-specific pages viewed outside their intended mode.

5. Issues Found & Fixed This Review Cycle

  1. Emoji badges on Member Profile — achievement badges (flame/trophy/dumbbell/sun) were emoji; replaced with stroke SVG icons consistent with the no-emoji rule. Dead emoji fields also removed from business-mode.js.
  2. Literal escape-sequence rot — many pages had literal text like \u2014 instead of an actual em dash, visible on screen as garbled text. Swept and fixed across 35+ files.
  3. Duplicate local card CSS — several newly built pages (Equipment, Trainer Workspace, Supplier Catalog Import, Supplier Scorecard, Kiosk Devices) redefined .mp-card locally instead of using the shared one; removed the duplicates in favor of the single definition in app-shell.css.
  4. Silent mode-blindness — six gym-specific pages (Members, Bookings, Trainer Workspace, Access Control, Equipment, Kiosk Devices) loaded business-mode.js but never checked it, so they'd render gym content even for a non-gym business reaching them directly. Added a shared, non-blocking mismatch banner (bmModeCheck()) to all six.
  5. Access Control / Kiosk Devices menu inconsistency — these pages used a bespoke sub-navigation row instead of the standard header pill-nav every other app group uses. Rebuilt onto the shared pill-nav pattern (Live Operations / Access Policies / Kiosk Devices, shared header "Access Control").
  6. Home page KPIs and Recommended Actions were inert — Business Snapshot stats and the 3 Recommended Actions were plain text with no destination. Every stat and advice line now carries a link and renders as a real, hover-affordant link to the page where the user can act on it.
  7. POS Daily Close / session-close bug — Daily Close lived as a sibling pill-nav tab next to Register. Navigating to it and back caused Point of Sale.html to reload from scratch with no session persistence, which reset the cashier to the PIN/float-count screen — reading as "the session got closed" even though the shift was still open. Fixed by: (a) persisting the active cashier session (owner, opening float, transactions) to localStorage and restoring it silently on load, and (b) removing Daily Close from the primary pill-nav — POS's customer-facing screen is now just "Point of Sale," with Daily Close, Switch User, and Close My Session tucked into a small overflow ("⋯") menu, matching how mainstream POS products (Square, Toast) keep the sale screen uncluttered.

7. Appendix: Maturity Labels

Per the World-Class Product Blueprint benchmark review, no feature should be called "complete" in release planning until it reaches Production-grade. Every item in this document's status tables (§4, §6) should be read against this scale, not a binary done/not-done.

LabelMeaning
DesignedUX and rules are specified.
ClickablePrototype path works with sample/local data — this is the honest status of nearly everything in this document.
Data-backedPersistent API and validated data model exist.
ControlledRoles, approvals and validations are enforced server-side.
ReconcilableMoney, stock and operational totals close correctly.
AuditableEvery material change can be attributed and reviewed.
Production-gradeSecurity, recovery, performance, accessibility, tests and support are proven.
