The app is functionally desktop-only. The single biggest cause is mechanical and cheap to fix: not one Hakiqa app page carries a <meta name="viewport"> tag — so every phone renders the ~980px desktop layout scaled down to unreadable. Beyond that, the shell is genuinely centralized (good), but three things block "one design system": responsive behaviour lives per-page and inconsistently, spacing / radius / shadow are still un-tokenised, and the slide-over panel is re-declared on 7 pages instead of living in the shell. None of this is a rebuild — most of it is one pass on app-shell.css / app-shell.js plus a short list of per-page wraps.

P0 — Blocks tablet & phone

These stop the app being usable on a real device. Fix first; most are single shell edits that cascade to all 54 pages.

P0-1No viewport meta tag on any app pageShell · 1 fix → all pages

Every in-app page ships only <meta charset="UTF-8">. Without a viewport tag, mobile browsers assume a ~980px canvas and shrink it to fit — so 22px headings render at ~8px and nothing is tappable. Only the out-of-scope Blackpaw / BICC / design-system files have the tag today.

Home Screen Concept.html:4 → charset only, no viewport
grep "name=\"viewport\"" → matches only in export/*, uploads/*, design_system*.html (all out of scope)
Fix: inject the tag once, synchronously, from the top of app-shell.js (it already runs in <head> before layout on every page). One line, zero per-page edits.
P0-2Shell has no phone tier — app-top crowds and clipsShell

app-shell.css carries only two breakpoints: 1180px (grids) and 860px (padding + hide search). The header row is flex-wrap:nowrap by design, so on a phone the back-title, centred pill-nav and the actions cluster (search + bell + avatar) compete in ~360px — the pill-nav scrolls but the row stays cramped and the title truncates.

assets/app-shell.css:114 .app-top{ flex-wrap:nowrap } · :430 @media(max-width:860px) only hides .search-box
Fix: add a shared ≤720px block in the shell that stacks app-top into two rows (title+actions, then full-width pill-nav) and reduces main padding further.
P0-3Rail is a fixed 76px column with no mobile formShell

The icon rail is width:76px, sticky, full-height, always visible. On a 360px phone that permanently consumes ~21% of the width with no way to reclaim it; on tablet portrait it's tolerable but heavy.

assets/app-shell.css:69 .rail{ width:76px; flex:0 0 76px; height:100vh }
Fix: under ~600px, convert the rail to a slim bottom tab bar (or a 56px slide-in drawer). One shared rule; markup already has the icon list to reuse.
P0-4Grid collapse cliff — N columns jump straight to 1Shell + per-page

Almost every layout collapses only at 1180px and goes directly to a single column, skipping a tablet 2-column tier. 4-up KPI rows either stay 4 (cramped ~834px tablet portrait) or drop to 1 (wasteful). Breakpoint values are also inconsistent page-to-page (1180 / 1000 / 900 / 880 / 860 / 720 all appear).

Analytics-Revenue:318, Exceptions:43, Company Brief:114, CEO Command Screen:154, Settings:63 … each defines its own single 1180px collapse
Fix: adopt a shared breakpoint scale (see P1-3) and give KPI/card rows a mid 2-col tier at ~820px so tablet portrait reads well before phone drops to 1-col.
P0-5Ledger tables force horizontal page scroll on phonePer-page

Purchase Orders correctly wraps its wide table in an overflow-x:auto card with a min-width. Expenses and Sales — Orders (and likely Sales Leaderboard / Statement) do not — their multi-column ledgers push the whole page wider than the phone viewport.

Inventory - Purchase Orders.html:17 .po-table-card{ overflow-x:auto } ✓
Expenses.html / Sales - Orders.html → no overflow-x wrapper on the table ✗
Fix: add one shared .table-wrap{overflow-x:auto} to the shell and wrap the un-wrapped ledger tables in it.
P0-6One slide-over panel lacks the mobile max-width guardPer-page

Every slide-over uses max-width:92vw so it never exceeds the phone — except CRM Pipeline's quick-edit panel, which is a bare width:400px. On a <400px phone it overflows the viewport.

CRM - Pipeline.html:84 .qe-panel{ width:400px } — missing max-width:92vw
(cf. Tasks:32, Members:81, Bookings:42, Access Control:56 all have the guard)
Fix: resolved for free by P1-4 (single shared slide-over); or add max-width:92vw if patched in place.

P1 — Bringing it under one design system

Structural consolidation. These are what make "one design system" true rather than aspirational.

P1-1Un-tokenised spacing, radius & shadowShell

Colour is fully tokenised; geometry is not. Card radii range 10–28px chosen ad hoc per page (18 / 20 / 22 / 24 all appear as "the card radius"), and shadows are one-off rgba() literals. This is the largest remaining single-system gap and the open todo from prior sessions.

radii seen: mp-card 18 · kpi-card 24 · tool-card 20 · scan-box 28 · back-btn 50% · shadows: bespoke rgba per component
Fix: add --space-*, --radius-*, --shadow-* scales to :root in the shell and migrate components to them.
P1-2Slide-over / overlay re-declared on 7 pagesShell + per-page

The same panel pattern is hand-rolled per page under different names with drifting widths — 400 / 420 / 440 / 480px — violating the project's own "one source of truth" rule.

qe-panel 400 (Pipeline) · tk-panel 400 (Tasks) · mem-panel 400 (Members) · roster-panel 420 (Bookings) · pol-panel 420 (Access Control) · session-panel 440 (Trainer) · slide-over 480 (Purchase Orders)
Fix: promote one .overlay + .slide-over (with a width modifier) into app-shell.css; delete the per-page copies.
P1-3No shared breakpoint strategyShell + docs

Six different max-widths are used as "the breakpoint" across pages. There is no documented tablet/phone contract, so every new page guesses.

1180 · 1000 · 900 · 880 · 860 · 720 all in use as collapse points
Fix: standardise on two (desktop→tablet ~1024, tablet→phone ~640) plus the existing content cap, and record the contract in CLAUDE.md.
P1-4Three competing design-system source docsHousekeeping

design_system.html, design_system copy.html and uploads/design_system_demo_v2.html are near-identical. The shell comment says the palette was standardised "from design_system copy.html," so the canonical source is ambiguous.

design_system.html · design_system copy.html · uploads/design_system_demo_v2.html (dup)
Fix: name one canonical reference, archive/delete the other two so there is a single documented source of truth.
P1-5Malformed rule in the shared stylesheetShell

A leftover fragment trails a valid rule in the shared file. Browsers discard it, but it's a defect sitting in the single source of truth (and the .mr-pill.risk intent is muddied).

assets/app-shell.css:285 … .mr-pill.risk{ background:var(--neg-bg); color:var(--neg); } 0.08 20); color:#a3231f; }
Fix: delete the trailing 0.08 20); color:#a3231f; } fragment.
P1-6Dark mode is shell-only by its own admissionShell + per-page

The dark-mode block covers shared chrome but explicitly excludes page-local components. Toggling dark on those pages leaves choice-cards, wizard cards and ledger tables in light styling.

assets/app-shell.css:436 comment: "Page-local components (choice-card, wiz-card, ledger tables, etc.) are not yet covered"
Fix: enumerate the uncovered page-local components and either token-migrate them or add their dark rules; ideally fold the repeated ones (ledger table) into the shell.

P2 — Rules & polish

Lower urgency, but needed for full compliance with the project UI rules once mobile works.

P2-1Touch targets below the 44px minimumShell

The project rules echo a 44px mobile hit-target floor. Rail icons (44px) pass, but the back-btn and bell icon-btn are 38px, and pill-nav links are ~34px tall (9px padding). Fine for mouse, tight for thumbs.

app-shell.css:130 back-btn 38 · :175 icon-btn 38 · :143 pill-nav a padding 9px 14px (~34px)
Fix: bump these to ≥44px inside the phone breakpoint only, so desktop density is untouched.
P2-2Search becomes unreachable on phoneShell

The 860px rule hides .search-box outright with no replacement, so search — a primary action on data pages — simply disappears on mobile.

assets/app-shell.css:432 .app-top .search-box{ display:none }
Fix: replace with a search icon-button that expands, so the capability survives on phone.
P2-3Kiosk / storefront pages need a device passPer-page

Fixed-size layouts (Events Check-in Kiosk scan panel 420px, Ambient Mode, Login / Sign Up) are built for a known screen. Kiosk is legitimately a fixed device (lower priority), but the customer-facing storefront and auth pages should confirm cleanly at 360px.

Events - Check-in Kiosk.html:22 .scan-panel{ width:420px } (fixed device — acceptable) · verify Login / Sign Up / Storefront at 360px
Fix: spot-verify the customer + auth flows at phone width; leave kiosk fixed but centred.
P2-4Re-verify closed rules after the responsive passQA

Prior audit (19 Jul) closed emoji-as-icon, one-hero-per-row and comma/K-M formatting. Responsive reflow can reintroduce violations (e.g. a hero card stacking next to another, or a wrapped number). Re-check after Phase 1.

AUDIT REPORT.md §3.2 / §3.3 — previously CLOSED; regression-check post-reflow
Fix: quick visual sweep of KPI rows and mascot/icon usage at phone width once layout changes land.

What is already healthy (do not regress)

Confirmed solid this pass:
  • Colour is fully tokenised (light + dark pairs) and consumed via var() across all 54 pages.
  • The shell (rail / app-top / pill-nav / hero cards / Haki tips / support widget) is genuinely centralized and injected once from app-shell.js.
  • Most slide-overs and modals already carry max-width:92vw — the responsive instinct exists, it's just uneven.
  • Wide tables where remembered (Purchase Orders) are correctly scroll-wrapped — the right pattern to generalise.
  • Newer storefront/customer pages already ship 900px breakpoints — closer to responsive than the core app.

Recommended sequence

1
Make it work on a phone (all P0)
Inject viewport from app-shell.js; add the phone tier to app-shell.css (stack app-top, collapse rail to a bottom bar, mid 2-col grid tier, .table-wrap); wrap the two un-wrapped ledger tables. Mostly one shell pass → cascades to every page.
2
Make it one system (P1)
Add spacing/radius/shadow token scales; promote a single .slide-over/.overlay into the shell and delete the 7 copies; document the breakpoint contract in CLAUDE.md; pick the canonical design-system doc; delete the malformed CSS fragment.
3
Polish & re-verify (P2)
Bump touch targets and restore phone search inside the phone breakpoint; device-check storefront/auth at 360px; regression-sweep the previously-closed UI rules after reflow.
