Eleven principles

What guides every decision.

These principles apply across research, interface design, engineering, deployment, support, and continuous improvement.

1

Begin with the outcome

Name the job before choosing screens, components, data structures, or technology.

2

Make the next action obvious

Use one primary action, finite choices, and progressive disclosure.

3

Let the system carry complexity

Use orchestration, defaults, automation, pre-filling, and reconciliation without hiding consequences.

4

Prevent before explaining

Constrain invalid choices, validate early, and preserve entered work.

5

Close every loop

Show what happened, what changed, what remains, and how to recover.

6

Design the whole state machine

Loading, empty, error, permission, offline, success, and recovery are part of the screen.

7

Reuse before invention

Select a canonical screen, then patterns, before creating a new standard.

8

Build for real conditions

Expect interruptions, slow networks, small screens, shared devices, and users under pressure.

9

Make trust inspectable

Make permissions, ownership, sources, consequences, audit trails, and recovery visible.

10

Ship safely and learn continuously

Release observable changes with automated gates, named owners, and rollback paths.

11

Earn “It just works”

Reliability, performance, security, accessibility, and supportability are product qualities.

The three-step constraint

Understand. Act. Confirm.

For a core task, aim for one obvious primary action and no more than three meaningful user steps. A meaningful step is a decision—not every click or system event. Safety and informed consent always outrank artificial brevity.

Release gate

Done means proven.

A screenshot, manual review, or passing build alone is not evidence that a Blackpaw product is ready.

  • Brand identity, Urbanist, tokens, and approved assets
  • Clear hierarchy and plain-language actions
  • Loading, empty, error, permission, success, and recovery
  • Responsive keyboard, touch, and assistive use
  • Security, privacy, roles, and auditability
  • Representative performance and network conditions
  • Automated, visual, and critical-task tests
  • Deployment, observation, support, and rollback ownership
  • DS-01–DS-13 conformance evidence from the same release
Builder path

Start from the system.

People and copilots follow the same sources and produce evidence against the same release.

  1. Read the agent instructions, brand quick guide, and canonical principles.
  2. Search the shared portal, screens, patterns, and components before creating anything new.
  3. Import semantic tokens and approved assets; choose the correct identity and expression.
  4. Define the core outcome and its three meaningful steps—or document why safety needs more.
  5. Implement every relevant state, breakpoint, permission, and recovery path.
  6. Run the brand and experience gates and attach evidence to the release.
